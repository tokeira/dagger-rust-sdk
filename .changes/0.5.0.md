## 0.5.0 - 2026-11-07

This release targets stock Dagger `v1.0.0-beta.25` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.5.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.5.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.25` engines and CLIs instead of `v1.0.0-beta.23`. Each Dagger release serves an API view of its own, and the SDK requires beta.25's, so a module must declare `engineVersion = "v1.0.0-beta.25"` in its `dagger-module.toml`. The generated client follows the beta.25 schema. It adds a `transparentHugePages` option for `Container.withExec`, and `include` and `exclude` options for `File.extract` by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/45

### Added
- A module can export a collection, as a Go module can: an object marked `#[dagger_sdk::object(collection)]`, whose `#[dagger(field, keys)]` holds its keys and whose `#[dagger(function, get)]` returns one item, with an optional `#[dagger(field, delta)]` that receives a `CollectionDelta`. Callers get the engine's `keys`, `list`, `get` and `subset` operations, and `dagger check` and `dagger generate` gain a flag that selects items by key. Each collection declares one `CollectionBase` field, which the engine fills with the collection that a value was derived from: a value built from the receiver keeps it, and a value built afresh from `CollectionBase::default()` is its own base by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/45
