## 0.6.0 - 2026-11-14

This release targets stock Dagger `v1.0.0-beta.27` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.6.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.6.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.27` engines and CLIs instead of `v1.0.0-beta.25`. Each Dagger release serves an API view of its own, and the SDK requires beta.27's, so a module must declare `engineVersion = "v1.0.0-beta.27"` in its `dagger-module.toml`. The generated client follows the beta.27 schema, which writes acronyms in field names as words and drops the legacy `ImageMediaTypes` and `ImageLayerCompression` spellings, so `GitBundle::prerequisite_sh_as` is now `prerequisite_shas`, `Container::experimental_with_all_gp_us` is now `experimental_with_all_gpus`, `ImageMediaTypes::OciMediaTypes` and `DockerMediaTypes` are now `Oci` and `Docker`, and `ImageLayerCompression::EStarGz` is now `Estargz`. The experimental `Query::format_identifiers` and `identifier` move to the `Naming` object that `Query::naming` returns, and `Query::naming_dictionary` becomes `Naming::dictionary`. The client also adds a `resolve_broken_symlinks` option for `Container::directory` and `Directory::directory`, a `key_by_content` option for `File::sync`, a `client_version` option for `ModuleSource::client_schema_introspection_json`, `Directory::with_platform`, and `WorkspaceSdk::scope_setting`. A module that declares beta.27 is named by the engine's new rules, as modules in every SDK are, so its callers may see some names spelled differently: a struct `HttpClient` in a module `tiny` is `TinyHTTPClient` rather than `TinyHttpClient`, and an enum variant `GitHub` is the member `GITHUB` rather than `GIT_HUB`. The module's Rust code does not change by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/48

### Dependencies
- The repository builds resolve `rustix` 1.1.6, which fixes RUSTSEC-2026-0486: its extended-attribute functions could mark unwritten bytes as initialized when given a zero-length buffer. The SDK never reaches those functions. Crates that depend on the SDK resolve their own `rustix` release, and `cargo update -p rustix` moves them to a fixed one by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/48
