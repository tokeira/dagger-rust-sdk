## 0.3.0 - 2026-10-23

This release targets stock Dagger `v1.0.0-beta.21` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.3.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.3.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.21` engines and CLIs instead of `v1.0.0-beta.19`. The generated client follows the beta.21 schema. It adds `Workspace.main`, `Workspace.withMain`, `Workspace.withoutMain`, `WorkspaceModule.main` and a `main` option for `Workspace.withInitModule` and `Module.serve`, and deprecates the `entrypoint` names they replace, which remain as aliases by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/33

### Fixed
- A module's generated files no longer depend on how its workspace was loaded. The operation manifest hashed the module's resolved pin, which only a workspace loaded from a Git reference sets, so a staleness check from a Git reference, such as `dagger check -W github.com/<owner>/<repo>@<commit>`, reported files generated in a checkout of the same commit as stale by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/28

### Dependencies
- The examples and repository builds resolve `rustls-webpki` 0.103.16 and `webpki-roots` 1.0.10, which fix RUSTSEC-2026-0382 and RUSTSEC-2026-0381: both stop trusting certificate paths through distrusted emSign intermediates. Crates that depend on the SDK resolve their own releases of both, and `cargo update -p rustls-webpki -p webpki-roots` moves them to the fixed ones by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/32
- The examples and repository builds resolve `tokio` 1.53.3, which fixes RUSTSEC-2026-0386: `AsyncFd`'s safe constructors could violate I/O safety. Crates that depend on the SDK resolve their own `tokio` release, and `cargo update -p tokio` moves them to a fixed one by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/33
