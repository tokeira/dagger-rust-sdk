## 0.4.0 - 2026-10-31

This release targets stock Dagger `v1.0.0-beta.23` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.4.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.4.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.23` engines and CLIs instead of `v1.0.0-beta.21`. From `v1.0.0-beta.22` each Dagger release serves an API view of its own, and the SDK requires beta.23's, so a module must declare `engineVersion = "v1.0.0-beta.23"` in its `dagger-module.toml`. The generated client follows the beta.23 schema. It adds `File.extract`, `Container.withMountedFiles`, a `sourceDateEpoch` option for `Container.publish`, `Container.export`, `Container.exportImage` and `Container.asTarball`, and a `followSymlinks` option for `Query.sshfsVolume`. It removes `ArtifactResult`, `Artifacts.values`, `Artifacts.withArtifacts` and `CollectionTypeDef.batchType`, which beta.23 drops without deprecation by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/38

### Added
- A module is described by its crate root's `//!` documentation, as a Go module is by its package documentation: the first line is the module's short description and the rest its long description. The `src/lib.rs` that `dagger module init` writes starts with a placeholder for the module's description by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/39

### Changed
- A new CLI session announces the SDK's target release with `dagger session --version`, as Dagger's Go SDK does from `v1.0.0-beta.22`, so the engine serves the API view the generated client was built for even when the session runs a CLI of another release, such as the `dagger` on `PATH` that the SDK falls back to. `ClientConfigBuilder::version` still overrides the announced release by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/38
- A module whose `engineVersion` selects another API view than the SDK's target is refused with a message that names the view the engine served and the `engineVersion` to declare, and the module authoring guide describes how to move a module to a new SDK release by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/38
- A handle made from an ID that a query returned, such as the result of `sync` or an element of a list of objects, keeps that ID, so passing it as an argument no longer asks the engine for its ID first, as Dagger's Go SDK does from `v1.0.0-beta.22`. As in the Go SDK, a handle that a module function receives still asks for its ID by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/39
