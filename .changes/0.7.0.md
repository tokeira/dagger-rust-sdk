## 0.7.0 - 2026-11-15

This release targets the Dagger `v1.0.0-beta.27` API view and runs on stock `v1.0.0-beta.27` engines and on later 1.x engines that serve that view. Applications depend on `tokeira-dagger-sdk = "0.7.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.7.0`.

### Changed
- The SDK runs on later Dagger engines. It accepts an engine of its target release, `v1.0.0-beta.27`, or of any later 1.x release that serves the `v1.0.0-beta.27` API view, which a module selects with `engineVersion = "v1.0.0-beta.27"` in its `dagger-module.toml` and a client gets from a `v1.0.0-beta.27` CLI. Before a session is used, the SDK asks the engine for its release and for the view it serves. An engine older than the target fails with the new `CompatibilityErrorKind::EngineTooOld`, an engine of another major version with `VersionMismatch`, and another view with the new `ViewMismatch`, whose message says how a module and a client select their view. `allow_unverified_compatibility` still waives only missing evidence, which now includes an engine that states no view (`CompatibilityEvidenceGap::MissingView`). Under `dagger run`, a client's session has the view of the CLI running the command, so that CLI must be `v1.0.0-beta.27` by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/51
- `dagger module init` writes the SDK's target release as the module's `engineVersion`, rather than the engine's release, so a module initialized on a later engine is served the API view that the SDK's bindings are compiled for by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/51
- Code generation accepts a later engine's copy of the target's API view. It compares the copy with the SDK's reviewed Core API by its wire contract: reworded documentation, new deprecations, and fields and optional arguments the SDK does not bind are accepted, while a removed or retyped coordinate, a changed default, a new required argument or input field, or a new enum value is refused. A module's operation manifest records the identity of the schema the SDK consumed rather than the bytes the engine sent, so the module's generated files stay current on such an engine. Moving a module generated by 0.6.0 to 0.7.0 takes one `dagger generate`, whose changes are committed with the move; until then the module fails to load with `GENERATED_STALE`, as after any SDK release. When a module's view is not the target, `dagger generate` tells the user of an engine older than the target to run the module on a newer one, and anyone else which `engineVersion` to declare by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/51

### Fixed
- Generation no longer fails for a module that depends on another module. The engine adds every object type of a module's dependencies to the possible types of Core's `Node` interface, since each has an ID, and 0.6.0 compared each Core interface's possible types with its reviewed Core API in full, so `dagger generate` failed with `SCHEMA_CORE_COORDINATE_INCOMPATIBLE` at `Node`, and the module could not load. Possible types are now compared over Core types only. The module's generated files bind the dependency's types, but a module cannot yet call a dependency or take its objects as arguments by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/51
