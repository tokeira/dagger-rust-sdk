## sdk/rust/v1.0.0-beta.11.rust.5 - 2026-10-17

This SDK uses 🚙 Engine + 🚗 CLI version `v1.0.0-beta.11.rust.5`, built from this repository at the release commit; the complete engine ships as a release artifact alongside the crate files.

📦 Released as checked repository artifacts (`dagger-sdk` and `dagger-sdk-macros` crate files plus the complete engines for both Linux architectures and the native macOS CLI); see sdk/rust/docs/namespace-build.md.

> Upgrading from `sdk/rust/v1.0.0-beta.11.rust.4`: modules generated by that release regenerate once. Remove the module's generated `src/dagger_generated/` directory, `src/bin/dagger-module.rs`, and `.dagger/` directory, then run `dagger generate`; authored files, including any other binaries under `src/bin/`, stay in place.

### Fixed
- New Rust modules declare `pub mod dagger_generated;`, and authoring discovery treats that crate-root module as generator-owned, so the starter crate compiles with its generated entrypoint and declaring the module no longer fails generation by @iw in https://github.com/iw/dagger/pull/95
- Module authoring failures report the compiler's diagnostic code, explanation, remediation, and authored source location instead of a generic authoring failure by @iw in https://github.com/iw/dagger/pull/95
- Exported functions may return `Result<T, dagger_sdk::ModuleError>` directly, or any error type that converts into `ModuleError`; authoring discovery treats the error as the bridge's conversion rather than an exported type by @iw in https://github.com/iw/dagger/pull/95
- Generated module dispatch and codecs name Core handles such as `Directory`, `File`, and `Llm` through their SDK paths, so modules whose functions take or return Core types compile by @iw in https://github.com/iw/dagger/pull/95
- Rust modules load: the runtime build step promotes the compiled module binary out of the Cargo target cache itself, so runtime finalization no longer tries to read the binary from a cache mount by @iw in https://github.com/iw/dagger/pull/95
- Module generation is idempotent: identical authored source regenerates identical bytes, because the generated `src/bin/dagger-module.rs` entrypoint no longer enters the authoring snapshot whose descriptor it embeds by @iw in https://github.com/iw/dagger/pull/95
- Module generation records its generated paths in the module's own `.gitattributes` relative to the module, so the entries match the generated files instead of repository-root spellings that match nothing by @iw in https://github.com/iw/dagger/pull/95
- `dagger generate` runs the installed Rust SDK's generators, so it regenerates Rust modules and clients after authored edits, including a module whose stale generated code keeps it from loading by @iw in https://github.com/iw/dagger/pull/95
- Rust modules return their registered type definitions to the engine: the generated registration publishes the module's ID as the registration call's return value instead of serving the module into the calling session, so the engine can load the module's functions by @iw in https://github.com/iw/dagger/pull/95
- Rust module constructors run when the engine invokes them: generated dispatch selects the constructor by the empty function name the engine sends, instead of the constructor's wire name, which never reaches the call by @iw in https://github.com/iw/dagger/pull/95
- Release verification carries a Rust module past initialization: against the completed engine it authors Core-handle and fallible exports, requires the stale load to name `dagger generate`, regenerates, requires a second generation to change nothing, and loads and calls the module. A candidate that fails any step fails verification by @iw in https://github.com/iw/dagger/pull/95
- Concurrent first-time loads of the same Rust module no longer fail each other's Cargo builds: the runtime mounts its Cargo registry, Git, and target caches with locked sharing, so simultaneous builds take turns instead of unpacking crates into the same registry at once by @iw in https://github.com/iw/dagger/pull/95

### Dependencies
- The SDK requires `zip` 9.0.4, which carries the fixes for RUSTSEC-2026-0367, RUSTSEC-2026-0368, and RUSTSEC-2026-0369 that affect every 8.x release. CLI provisioning copies one regular archive member by index and never calls the extraction APIs those advisories describe by @iw in https://github.com/iw/dagger/pull/95
- The examples and repository builds resolve `rustls` 0.23.46, which carries the fixes for RUSTSEC-2026-0285, RUSTSEC-2026-0346, RUSTSEC-2026-0348, and RUSTSEC-2026-0349. Crates that depend on the SDK continue to resolve their own `rustls` release by @iw in https://github.com/iw/dagger/pull/95
