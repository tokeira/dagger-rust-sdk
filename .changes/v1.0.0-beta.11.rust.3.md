## sdk/rust/v1.0.0-beta.11.rust.3 - 2026-08-19

This SDK uses 🚙 Engine + 🚗 CLI version `v1.0.0-beta.11` (fork build `rust.3`, reported as `v1.0.0-beta.11+rust.3.<commit>`), built from this repository at the release commit; the complete engine ships as a release artifact alongside the crate files.

📦 Released as checked repository artifacts (`dagger-sdk` and `dagger-sdk-macros` crate files plus the complete engine); see sdk/rust/docs/namespace-build.md.

### Changed
- The engine and CLI now identify as the upstream tag (`v1.0.0-beta.11`) with the fork iteration and build commit carried in semver build metadata (`+rust.3.<commit8>`), so version gating and module `engineVersion` pins interoperate with upstream engines of the same base while `dagger version` still distinguishes fork builds. The SDK's connection validator matches the fork iteration and the metadata's form; release verification separately requires the fork marker, which conformance engines built from the unmodified upstream tree deliberately do not carry by @iw in https://github.com/iw/dagger/pull/85

### Fixed
- The shipped complete engine is now built from this fork's workspace source instead of the upstream-pinned conformance revision, so fork engine corrections (the Void null encoding among them) actually ship in the release artifact. The upstream pin remains as the schema-conformance contract, and upstream `v1.0.0` bumps continue to arrive by merging upstream tags into main by @iw in https://github.com/iw/dagger/pull/84 \
  Release verification now carries a discriminating canary: the external consumer exercises a bare `Void` field (`Container.exportImage`), whose pre-correction `{}` encoding strict decoding refuses — the nullable `Void` path checked previously was JSON null on both engine generations and could not catch the regression. The `sdk/rust/v1.0.0-beta.11.rust.2` engine artifact was affected: its notes carry an erratum, and its crates pair correctly only with this release's engine.
