## 0.3.1 - 2026-10-24

This release targets stock Dagger `v1.0.0-beta.21` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.3.1"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.3.1`.

### Changed
- When a module function returns a query that failed in transport with `?`, its error ends with the I/O failure at the root of the transport error, such as `the engine transport failed: timed out (os error 110)`. It names only the failure's kind and operating system code, never the transport library's own message, which can carry credentials by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/35

### Fixed
- A query no longer fails when one reply to a TCP keepalive probe goes missing while the engine works on it. On Linux, the SDK's connection to the engine kept Reqwest's default `TCP_USER_TIMEOUT` of 30 s, so the kernel reset it after a single unanswered probe, and the query failed with "the engine transport failed". The connection now keeps alive like the Go SDK's: a probe after 15 s of silence, then one every 15 s, and it gives up only after 9 unanswered probes by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/35

## 0.3.0 - 2026-10-23

This release targets stock Dagger `v1.0.0-beta.21` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.3.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.3.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.21` engines and CLIs instead of `v1.0.0-beta.19`. The generated client follows the beta.21 schema. It adds `Workspace.main`, `Workspace.withMain`, `Workspace.withoutMain`, `WorkspaceModule.main` and a `main` option for `Workspace.withInitModule` and `Module.serve`, and deprecates the `entrypoint` names they replace, which remain as aliases by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/33

### Fixed
- A module's generated files no longer depend on how its workspace was loaded. The operation manifest hashed the module's resolved pin, which only a workspace loaded from a Git reference sets, so a staleness check from a Git reference, such as `dagger check -W github.com/<owner>/<repo>@<commit>`, reported files generated in a checkout of the same commit as stale by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/28

### Dependencies
- The examples and repository builds resolve `rustls-webpki` 0.103.16 and `webpki-roots` 1.0.10, which fix RUSTSEC-2026-0382 and RUSTSEC-2026-0381: both stop trusting certificate paths through distrusted emSign intermediates. Crates that depend on the SDK resolve their own releases of both, and `cargo update -p rustls-webpki -p webpki-roots` moves them to the fixed ones by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/32
- The examples and repository builds resolve `tokio` 1.53.3, which fixes RUSTSEC-2026-0386: `AsyncFd`'s safe constructors could violate I/O safety. Crates that depend on the SDK resolve their own `tokio` release, and `cargo update -p tokio` moves them to a fixed one by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/33

## 0.2.0 - 2026-10-20

This release targets stock Dagger `v1.0.0-beta.19` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.2.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.2.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.19` engines and CLIs instead of `v1.0.0-beta.18`. The generated client follows the beta.19 schema. It adds the `Identifier`, `IdentifierWord` and `NamingTerm` types, the `AcronymStyle`, `Casing` and `IdentifierWordKind` enums, `Query.identifier`, `Query.formatIdentifiers`, `Query.namingDictionary`, `Agent.parent`, `Artifact.workspace`, `Expertise.artifact`, `GitCommit.treeSHA`, `LLM.expertise` and an `expertise` option for `LLM.spawn`, and drops `LLM.recompose`, which beta.19 removed by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/26

### Changed
- Modules the runtime initializes depend on the SDK at the runtime's own version. Installed from a release's tag, `vX.Y.Z`, the runtime has them depend on that release from crates.io, as `dagger-sdk = { package = "tokeira-dagger-sdk", version = "=X.Y.Z" }`, and installed from any other reference, on the commit that reference resolves to, through Git. The runtime builds its SDK content from its own commit, so `runtime/assets/sdk-dependency.json`, which pinned that content to another commit, is gone by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/24

## 0.1.0 - 2026-10-19

This release targets stock Dagger `v1.0.0-beta.18` engines and CLIs. Applications depend on `tokeira-dagger-sdk = "0.1.0"` from crates.io, which brings `tokeira-dagger-sdk-macros` at the same version, and modules install the runtime from `github.com/tokeira/dagger-rust-sdk/runtime@v0.1.0`.

### 🔥 Breaking Changes
- The SDK targets stock Dagger `v1.0.0-beta.18` engines and CLIs instead of the fork's `v1.0.0-beta.11.rust.N` builds, and its compiled CLI downloads from dl.dagger.io. The generated client follows the beta.18 schema. It adds types such as `AgentMessage`, `Artifact`, `GitRemote` and the `Bytes` scalar, and drops those beta.18 removed, including `CurrentModule.asSDK`, `AgentGroup`, `CheckGroup`, `GeneratorGroup` and `UpGroup` by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/3
- Module clients and module dependencies are not generated yet. A scope that records them is refused before anything is written, until the SDK defines Rust clients for beta.18's client scopes by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/4
- The SDK is published as `tokeira-dagger-sdk`, with the `tokeira-dagger-sdk-macros` companion, and its versions start at `0.1.0`. Code still names the crate `dagger_sdk`, so a project changes only its `Cargo.toml` dependency. Generated projects record it as `dagger-sdk = { package = "tokeira-dagger-sdk", … }` by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/5

### Added
- The runtime installs on stock Dagger engines as an SDK module, with `dagger install github.com/tokeira/dagger-rust-sdk/runtime@<ref>`. `dagger module init rust` scaffolds a Rust module and writes its `dagger-module.toml`, and `dagger generate` regenerates it. The runtime builds its SDK content from the commit pinned in `runtime/assets/sdk-dependency.json`, so no engine has to package it by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/4

### Changed
- Modules the runtime initializes now depend on the renamed package, as `dagger-sdk = { package = "tokeira-dagger-sdk", git = "https://github.com/tokeira/dagger-rust-sdk", rev = … }`, at a commit with the new name. The SDK content the runtime builds carries NOTICE beside LICENSE by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/8
- The SDK needs Rust 1.99.1, up from 1.97.1. Its minimum supported Rust version, the toolchain that generated projects pin, and the image the runtime builds modules with all move to 1.99.1 by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/19

### Fixed
- Void results decode from stock Dagger engines, which return either `null` or an empty object; any other shape is still refused by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/3
- Generated module files are the same on every engine platform. Their generator identity named the tools' platform-specific executables, so files generated on an arm64 engine were stale on amd64, and `dagger generate` and the staleness check there failed with `OPERATION_MANIFEST_STALE`. Regeneration after a runtime upgrade, which changes the generator and SDK dependency, now replaces the files the prior manifest owns instead of refusing by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/12
- The `src/lib.rs` that `dagger module init rust` writes is rustfmt-formatted. Its template lost every indent by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/13
- Generated module code compiles without warnings under `-D warnings`, so a module no longer needs lint exceptions for it. Dispatch tripped `clippy::get_first`, the codec of an enum with a deprecated variant tripped `deprecated`, registration of an enum tripped `unused_mut`, and a custom scalar left an unused definition by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/13
- A module function that returns a failed query with `?` reports the engine's error. An execution failure keeps the engine's message, whose trace origin lets the CLI show the failed command and its output, and its command, exit code and output as details, where they fit. An argument that failed to resolve reports the engine's error behind it, and a request failure names its SDK causes, such as "the engine transport failed". Before, these read only "the engine execution failed", "the GraphQL query could not be built" and "the GraphQL query request failed" by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/14
- `dagger module init rust` inside a Cargo workspace that neither lists nor excludes the new module now says so, and names the path to add to that workspace's `exclude` or `members`. It reported only "Cargo dependency resolution failed" by @iw in https://github.com/tokeira/dagger-rust-sdk/pull/14
