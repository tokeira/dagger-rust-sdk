## sdk/rust/v1.0.0-beta.11.rust.1 - 2026-08-16

This SDK uses 🚙 Engine + 🚗 CLI version `v1.0.0-beta.11.rust.1`, built from this repository at the release commit; the complete engine ships as a release artifact alongside the crate files.

📦 Released as checked repository artifacts (`dagger-sdk` and `dagger-sdk-macros` crate files plus the complete engine); see sdk/rust/docs/namespace-build.md.

### 🔥 Breaking Changes
- Require Rust 1.97.1 and adopt edition 2024 for the Rust SDK crates by @iw in https://github.com/iw/dagger/pull/1 \
  The pinned development toolchain, declared MSRV, CI checks, and standalone examples now share this baseline. Users building the SDK from source must use Rust 1.97.1 or newer.
- Replace the legacy monolithic Rust generated client with target-pinned, schema-complete core bindings by @iw in https://github.com/iw/dagger/pull/35 \
  Generated types now live in generator-owned modules with corrected Rust names, option and input-object shapes, interface handles, typed ID conversions, enum wire mappings, deprecation markers, and public documentation. The supported generated surface remains re-exported from `dagger_sdk`, but code that depended on a beta-era generated name or shape may need to adopt its corrected equivalent.

### Added
- Add the Rust SDK's typed client foundations for configuration, injected connections, diagnostics, errors, and lossless raw GraphQL values by @iw in https://github.com/iw/dagger/pull/16 \
  Configuration construction is now pure and duration-based, public failures retain inspectable causes without rendering sensitive source text, and raw GraphQL responses preserve partial data, ordered errors, extensions, and the distinction between absent and explicit null data.
- Add target-pinned built-in engine integration for the Rust SDK by @iw in https://github.com/iw/dagger/pull/40 \
  The engine now packages private Rust initialization, generation, runtime, and protocol adapters with manifest-owned output, immutable dependency and toolchain policy, clean runtime construction, focused positive and negative verification, and capability-local completeness evidence. This establishes the engine hooks without claiming the separately scoped complete module-authoring or standalone-client surfaces.
- Document the beta Rust SDK's engine-free development and completed-engine release-assembly boundaries by @iw in https://github.com/iw/dagger/pull/71 \
  The `1.0.0-beta.11.rust.1` packages target Dagger `v1.0.0-beta.11`; assembly exports exactly the two public crate artifacts plus a complete `linux/amd64` engine and verifies one isolated external Rust consumer. The build performs no publication.
- Module cancellation is now real: the entrypoint installs a termination-signal producer, so SIGTERM/SIGINT trip the `ModuleCancellation` that authored code and the dispatcher observe. A cancelled call publishes one structured cancelled error as its terminal record, completed results are published without racing cancellation, and the unreachable result-election scaffolding was removed. (The definitive Go SDK offers no module cancellation; this is an intentional Rust extension. Engine-side SIGTERM-with-grace for function-call execs is the documented follow-up that makes engine teardown trigger it.) by @iw in https://github.com/iw/dagger/pull/72

### Changed
- The published `dagger-sdk` crate no longer packages example application scaffolding (~8.6 MB of lockfiles and assets); example sources remain. `dagger-sdk-macros` now ships its LICENSE. Changelog metadata reflects the repository-artifact release model instead of crates.io, and no longer links the Node.js SDK documentation by @iw in https://github.com/iw/dagger/pull/72

### Removed
- Removed the legacy beta connector (`crates/dagger-sdk/src/core`) and its transitional error types. The unreachable tree carried the pre-1.0 downloader, HTTP client, and session code plus seven dependency trees (eyre, derive_builder, graphql_client, hex-literal, platform-info, thiserror, which) that no live code used; the published crate no longer compiles or ships any of it by @iw in https://github.com/iw/dagger/pull/72

### Fixed
- The module code generator now reports its Result-arity diagnostic for return types shaped like `std::io::Result<()>` instead of panicking, for exported functions and for interface methods whose `Result` generics carry no type arguments by @iw in https://github.com/iw/dagger/pull/72
- CLI provisioning no longer performs blocking filesystem work on the async runtime thread: archive downloads write through an async handle, and extraction, cache publication, and retention pruning run on the blocking pool. The cache lock became a cancellable try-lock poll (replacing a kernel-blocking flock whose thread detached on cancellation), and file locking now uses the standard library, removing the fs4 dependency by @iw in https://github.com/iw/dagger/pull/72

### Security
- Built query documents, which inline argument literals including secret plaintexts, are no longer rendered into TRACE telemetry. The source policy now forbids direct telemetry in client foundations so this class of leak cannot return by @iw in https://github.com/iw/dagger/pull/72
